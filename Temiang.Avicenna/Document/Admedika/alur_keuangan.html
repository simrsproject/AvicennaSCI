Alur AdMedika — Keuangan

Proses pre-register E-Bill (enquiry sampai pengiriman dokumen) serta pelacakan invoice dan rincian klaim per invoice.

Sumber: PRE_REGISTER_EBILL.pdf, INVOICE_TRACKING.pdf.

1. Konsep

Dua alur terpisah: pre-register E-Bill dan pelacakan invoice.

PRE_REGISTER_EBILL_ENQUIRYdaftar klaim siap E-Bill
→
PRE_REGISTER_EBILLkirim klaim + dokumen · surat jalan
INVOICE_TRACKINGcari invoice · ringkasan klaim
→
INVOICE_TRACKING_DETAILSrincian klaim per invoice

PRE_REGISTER_EBILL_ENQUIRY menampilkan klaim yang sudah siap diajukan sebagai E-Bill untuk payor dan periode tertentu. Klaim terpilih kemudian dikirim lewat PRE_REGISTER_EBILL bersama dokumen pendukung (multipart). Hasilnya berupa tautan surat jalan.

INVOICE_TRACKING dipakai untuk memantau invoice yang sudah terbentuk, sedangkan INVOICE_TRACKING_DETAILS menampilkan klaim-klaim di dalam satu invoice beserta nominal dan statusnya.

2. Alur pre-register E-Bill

  1. PreRegisterEbillEnquiry Wajib

    Mengambil daftar klaim berdasarkan payorCode, coverage, dan periode.

    Butuh payorCode (simpan saat eligibility), coverage (RJ/RI), dateFrom, dateTo (DDMMYYYY).

  2. Pilih klaim

    Tentukan klaim yang akan diajukan; kumpulkan clID dan total tagihan.

    Jumlah klaim terpilih (totSelectedClaims) dihitung otomatis oleh service.

  3. PreRegisterEbill Wajib

    Mengirim klaim terpilih beserta dokumen (receipt dan dokumen terkait) sebagai multipart.

    Butuh invoiceNo, invoiceDate, preparedBy, totAmountDue, dan daftar selectedClaims. files boleh kosong.

  4. Simpan hasil

    Respons berisi surat_jalan_link dan status per klaim.

    Tampilkan tautan surat jalan dan catat status tiap clID.

if (!srv.IsOk(result, out message))

3.2 PreRegisterEbill (multipart)

// perlu: using System.IO;
var files = new[]
{
    new AdmedikaFile
    {
        FileName = "receipt.pdf",
        ContentType = "application/pdf",
        Content = File.ReadAllBytes(@"C:\dokumen\receipt.pdf")
    }
};

var request = new PreRegisterEbillPayload
{
    PayorCode = "ADMEDKA",
    Coverage = "RJ",
    DateFrom = "01102026",
    DateTo = "08102026",
    InvoiceNo = "INV-20261002-001",
    InvoiceDate = "02102026",
    PreparedBy = "user01",
    TotAmountDue = "100000",
    SelectedClaims = new[]
    {
        new PreRegisterEbillSelectedClaim { ClID = "xx650092" },
        new PreRegisterEbillSelectedClaim { ClID = "xx650087" }
    }
};

var result = srv.PreRegisterEbill(request, files);

if (!srv.IsOk(result, out message))
{
    ShowError(message);   // 1810 bila jumlah klaim tidak cocok
    return;
}

OpenUrl(result.SuratJalanLink);   // surat jalan pre-regist
foreach (var claim in result.SelectedClaims)
{
    // claim.ClID, claim.Status
}

6. Kode respons yang sering muncul

KodeArtiMuncul saat
1840Not foundPayor, invoice, atau klaim tidak ditemukan
1810Not matchJumlah/komposisi data tidak cocok (mis. total klaim)
1813Terminal not foundTerminal ID tidak terdaftar pada payor
1829Tanggal tidak validFormat tanggal bukan DDMMYYYY
1999Cannot be emptyField wajib kosong (payorCode/invoiceNo)

Semua respons bisnis tetap HTTP 200. Periksa TechnicalError → IsSuccess → ErrorCode/ErrorDesc, bukan HTTP status.

7. Contoh urutan terverifikasi

# pre-register E-Bill rawat jalan PreRegisterEbillEnquiry → daftar klaim siap E-Bill PreRegisterEbill (multipart) → surat_jalan_link + status klaim # pelacakan invoice InvoiceTracking → daftar invoice + total InvoiceTrackingDetails → rincian klaim per invoice

8. Catatan operasional

  • payorCode disimpan saat eligibility; dipakai untuk enquiry, pre-register, dan detail invoice.
  • totSelectedClaims dan totItems dihitung otomatis oleh service; jangan diisi manual.
  • Untuk pencarian invoice spesifik, isi invoiceNo lengkap dan biarkan dateName kosong.
  • Dokumen E-Bill dikirim sebagai multipart: field data (JSON) dan files.
  • Nominal dari gateway diteruskan apa adanya; jangan memformat ulang sebelum menyimpan.
  • Simpan surat_jalan_link dan status per clID untuk audit.
