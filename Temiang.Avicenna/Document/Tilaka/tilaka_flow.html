1. Arsitektur: dua produk, dua jaringan

Tilaka tidak dipakai sebagai satu layanan tunggal. Ada dua komponen yang berbeda secara teknis dan operasional:

Sign Plus — API cloud

https://sb-api.tilaka.id (sandbox)
https://api.tilaka.id (production)

  • Registrasi & aktivasi sertifikat dokter.
  • OAuth2 client credentials + mTLS (bila diwajibkan).
  • Webview registrasi, aktivasi, ubah MFA, ubah tampilan TTD.
  • Callback Registration (hasil KYC) dan Certificate Status.
  • Server Avicenna harus dapat diakses dari internet untuk callback.

Quick Sign — tilaka-lite on-prem

https://<host-rs>:8088

  • Upload PDF, request sign, cek status, unduh hasil.
  • Berjalan di Docker: tilaka-lite + MinIO + MariaDB.
  • Autentikasi sistem: client id/secret + IP whitelist.
  • Tanda tangan dilakukan setelah user punya auth session.
  • Tidak memerlukan akses internet untuk signing (kecuali auth user).

Alur besar

Dokter terdaftar→ Sertifikat aktif→ File Casemix→ Quick Sign user→ Template TTD→ Request sign→ Auth webview→ Callback / polling→ PDF bertanda tangan
Poin penting: Quick Sign hanya bisa dipakai dokter yang sudah memiliki sertifikat Aktif (status 3) dan sudah didaftarkan sebagai Quick Sign user. Jadi Fase 2 selalu bergantung pada Fase 1.

2.2 Kredensial dan pendaftaran ke Tilaka

  • Channel ID dan channel secret untuk Sign Plus dan Quick Sign.
  • Sertifikat mTLS (bila diwajibkan) beserta password, dipasang di server Avicenna.
  • IP publik server Avicenna didaftarkan ke Tilaka — allowlist ada di sisi Tilaka, bukan di aplikasi.
  • URL callback yang didaftarkan: https://<host>/TilakaCallback/Registration dan https://<host>/TilakaCallback/CertificateStatus.
  • URL redirect webview: https://<host>/TilakaWebview/Return.
  • Teks dan versi TnC final dari legal RS; disimpan di C:\Tilaka\TilakaConsent.txt dan TilakaConsentVersion.

3. Fase 1 — Registrasi dan aktivasi sertifikat dokter

Fase ini sudah diimplementasikan. Hasil akhirnya: dokter memiliki tilaka_name dan sertifikat berstatus Aktif.

3.1 Persiapan data dokter

  1. Paramedic.NamaKTP terisi sesuai KTP (bukan nama bergelar).
  2. Paramedic.Ssn berisi NIK tepat 16 digit dan tidak dipakai dokter lain.
  3. Paramedic.Email terisi dan aktif (dipakai OTP).
  4. Admin mengunggah foto KTP di halaman Tilaka; file disimpan di C:\Tilaka\KTP\{ParamedicID}\{ssn}_{yyyyMMddHHmmss}.jpg.

3.2 Langkah registrasi

Jebakan yang sering terjadi:
  • Membuat UUID baru saat request lama masih hidup → Tilaka menolak “NIK sedang dalam proses pendaftaran/verifikasi”. Gunakan Lanjutkan.
  • Nama di ParamedicName memuat gelar sehingga tidak cocok dengan Dukcapil. Gunakan NamaKTP.
  • Foto KTP terlalu besar → 413 Request Entity Too Large. Kompres sebelum kirim.
  • Jam server tidak sinkron → HMAC callback ditolak.

3.3 Panduan langkah demi langkah (operator)

Bagian ini adalah urutan klik di aplikasi, dari daftar dokter sampai webview Tilaka terbuka.

A. Membuka halaman registrasi

  1. Login ke Avicenna dengan user yang memiliki akses menu 01.23.01.
  2. Buka menu Tilaka E-Signature → Monitoring & Registrasi Sertifikat Dokter (Module/RADT/Tilaka/TilakaRegistrationList.aspx).
  3. Isi kolom Dokter atau pilih status Belum terdaftar, lalu klik Search.
  4. Pada baris dokter, klik Detail di kolom Action. Halaman terbuka: TilakaRegistrationDetail.aspx?md=view&id=<ParamedicID>.

B. Memeriksa data dan memulai pendaftaran

  1. Periksa Nama sesuai KTP, NIK (SSN), dan Email. Bila salah, perbaiki di master dokter lalu buka ulang halaman ini.
  2. Unggah Foto KTP (JPEG/PNG). File disimpan ke C:\Tilaka\KTP\{ParamedicID}\{ssn}_{yyyyMMddHHmmss}.jpg.
  3. Centang “Dokter telah membaca dan menyetujui TnC Tilaka.”
  4. Klik Daftar. Sistem memanggil /generateUUID. Status berubah menjadi UuidTerbit dan muncul pesan untuk melanjutkan Kirim Data KYC.
  5. Klik Kirim Data KYC. Sistem mengirim data + foto KTP + consent ke /registerForKycCheck. Status menjadi MenungguKyc.

C. Membuka webview registrasi

Tombol Buka Webview muncul saat status MenungguKyc, atau KycGagal untuk melanjutkan manual form. Pada status UuidTerbit tombol ini belum tersedia — selesaikan dulu Kirim Data KYC.

  1. Klik Buka Webview. Tab baru terbuka ke personal-webview/guide?request_id=...&redirect_url=....
  2. Di webview: masukkan OTP yang dikirim ke email dokter, lalu ikuti liveness.
  3. Buat Tilaka Name dan kata sandi. Bila gagal Dukcapil, ikuti Manual Form (data harus sama persis dengan yang dikirim).
  4. Setelah halaman selesai, klik Kembali ke Halaman Utama. Browser kembali ke /TilakaWebview/Return?request-id=....
  5. Kembali ke halaman detail Avicenna, klik Cek Status bila status belum berubah.

D. Aktivasi sertifikat

Setelah callback Certificate Status masuk dan status menjadi SertifikatTerbit, tombol Buka Webview yang sama sekarang membuka webview aktivasi (link-account), bukan webview registrasi.

  1. Klik Buka Webview.
  2. Login dengan Tilaka Name dan kata sandi, setujui informasi sertifikat, atur tampilan tanda tangan dan MFA.
  3. Klik Kembali ke Halaman Utama; halaman return menampilkan “Aktivasi selesai. Status: Aktif”.
  4. Klik Cek Status untuk memastikan status akhir Aktif.
Bila macet: gunakan Cek Status di halaman detail. Callback Tilaka bisa tertunda; tombol ini memanggil /userregstatus lalu /checkcertstatus. Tombol Cek Status Massal di halaman list memeriksa maksimal 5 record per klik.

4. Fase 2 — Quick Sign (tanda tangan dokumen)

4.1 Data file Casemix (read-only)

Data dokumen yang akan ditandatangani sudah tersedia di tabel TilakaCasemixFile. Modul ini tidak melakukan input, unggah, edit, atau hapus — hanya menampilkan dan memproses.

  1. Modul membaca baris TilakaCasemixFile dan menampilkan RegistrationNo, ParamedicID, FileName, FilePath.
  2. File fisik dibaca dari FilePath saat request signing; isinya harus PDF (Quick Sign tidak menerima format lain).
  3. Kolom Action berisi tombol Process Signature yang hanya tampil untuk baris yang belum diproses.
  4. Menekan tombol menjalankan request sign dengan signer = dokter ParamedicID, posisi tanda tangan 1/1/1/1/1, lalu menampilkan status per signer dan tautan auth webview.
  5. Baris yang sudah diproses menampilkan status request terbaru; tombol Process Signature tidak ditampilkan lagi.
Satu file boleh diajukan lebih dari sekali (mis. signing gagal atau perlu koreksi). Status file diturunkan dari request terbaru: Belum diproses, Requested, InProgress, Completed, Failed. Tidak ada kolom status terpisah di TilakaCasemixFile.

4.2 Onboarding Quick Sign user

Syarat: sertifikat dokter Aktif dan TilakaName terisi.

POST {TilakaLiteBaseUrl}/addquicksignusers
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "users": [
    { "email": "dokter@rs.example" }
  ]
}

Respons berisi status per email. Error yang mungkin: User does not exist, User is already registered for Quicksign, User does not have active certificate, Interval tidak valid, sertifikat user akan expired pada ....

4.3 Template tanda tangan

Setiap signer membutuhkan template yang terdaftar. Satu user boleh punya lebih dari satu template.

POST {TilakaLiteBaseUrl}/quicksign-addtemplates
Authorization: Bearer <access_token>

{
  "templates": [
    {
      "file_name": "Template TTD Dokter",
      "template_number": "TTD-DR-01",
      "template_file": "<base64 PDF>",
      "assigned_users": [
        { "user_identifier": "dokter001", "email": "dokter@rs.example" }
      ]
    }
  ]
}

Batas 5 template/user per panggilan. Menambah template baru membatalkan auth session user; user harus aktivasi ulang.

4.4 Membuat request tanda tangan

File Casemix→ Pilih signer→ Atur posisi→ Upload ke Tilaka→ Request sign→ Auth webview→ Signing→ Unduh

Upload file Casemix ke tilaka-lite

Aplikasi membaca file dari TilakaCasemixFile.FilePath, lalu mengirimkannya ke Tilaka. Nama file lokal tidak dipakai untuk request signing.

POST {TilakaLiteBaseUrl}/api/v1/upload
Authorization: Bearer <access_token>
Content-Type: multipart/form-data

file = <dokumen.pdf>

Response: { "success": true, "message": "File uploaded successfully",
            "filename": "b95d459d34cb4836977d_Test Document.pdf" }

Simpan filename persis. Nama file lokal tidak boleh dipakai untuk request sign.

Request sign

POST {TilakaLiteBaseUrl}/api/v1/requestquicksign
Authorization: Bearer <access_token>

{
  "request_id": "AVC-20261120-0001",
  "signatures": [
    {
      "user_identifier": "dokter001",
      "email": "dokter@rs.example",
      "signature_image": "<base64 jpeg/png>",
      "sequence": 1
    }
  ],
  "list_pdf": [
    {
      "filename": "b95d459d34cb4836977d_Test Document.pdf",
      "template_no": "TTD-DR-01",
      "signatures": [
        {
          "user_identifier": "dokter001",
          "width": 1,
          "height": 1,
          "coordinate_x": 1,
          "coordinate_y": 1,
          "page_number": 1,
          "reason": "Menyetujui isi dokumen",
          "location": "Jakarta",
          "qr_option": "QRCOMBINE"

}
  • request_id unik global, maks 50 karakter.
  • sequence wajib untuk lebih dari satu signer.
  • qr_option: QRONLY atau QRCOMBINE (opsional).
  • signature_image dapat diisi per signer dan per tanda tangan.
  • Posisi tanda tangan saat ini memakai nilai tetap page_number=1, coordinate_x=1, coordinate_y=1, width=1, height=1.

Respons auth

{
  "success": true,
  "message": "request quicksign success",
  "auth_response": [

Cek status

{ "request_id": "AVC-20261120-0001" }

Response:
{
  "success": true,
  "message": "DONE",
  "status": [
    { "sequence": 1, "status": "DONE", "user_identifier": "dokter001",
      "num_signatures": 1, "num_signatures_done": 1 }

  "list_pdf": [
    { "filename": "...", "error": false, "presigned_url": "https://..." }
  ]
}

Status per signer: UNAUTHORIZED, PROCESS, DONE, FAILED, DENIED.

Callback signing

POST {Avicenna}/TilakaCallback/Signing

{
  "success": true,
  "message": "DONE",
  "request_id": "AVC-20261120-0001",
  "user_info": {
    "sequence": 1, "status": "DONE", "user_identifier": "dokter001",
    "num_signatures": 1, "num_signatures_done": 1
  },
  "sign_info": [
    { "filename": "...", "status": "DONE", "presigned_url": "https://..." }
  ]
}

Callback dikirim per signer. Aplikasi harus idempoten dan tidak menurunkan status yang sudah DONE.

Unduh hasil

  • Gunakan presigned_url dari callback/status. URL berlaku terbatas (default 86400 detik).
  • Bila kedaluwarsa: GET {TilakaLiteBaseUrl}/getpresignurl?filename=<filename>.
  • Simpan salinan ke C:\Tilaka\Signed\<request_id>\<filename> dan catat path relatifnya.
  • Unduh ke user lewat handler ber-ProgramID, bukan URL publik langsung.

4.5 Monitoring auth session

GET {TilakaLiteBaseUrl}/quicksign-authsessions?email=&auth_status=active&page_number=1&limit=25
Authorization: Bearer <access_token>

auth_status: active, expired, not_activated. Dipakai untuk melihat siapa yang perlu aktivasi ulang sebelum signing.

4.6 Kuota dan batasan

  • Aktivasi auth session memotong kuota sebanyak jumlah template user.
  • Menambah template baru memotong kuota dan membatalkan auth session.
  • Setiap tanda tangan pada dokumen memotong kuota sesuai jumlah signature.
  • Satu request dapat berisi beberapa signer dan beberapa halaman.

8. Checklist go-live

Fase 1

  • SQL TilakaRegistration + kolom Paramedic.NamaKTP dijalankan; stored procedure diperbarui.
  • Key Tilaka* terisi; folder C:\Tilaka + ACL siap.
  • URL callback dan IP publik didaftarkan ke Tilaka.
  • Menu 01.23.01 aktif untuk user group.
  • Satu dokter uji menyelesaikan registrasi sampai Aktif.
  • Callback valid dan negatif (signature salah) teruji.

Fase 2

  • Data TilakaCasemixFile sudah tersedia dan dapat dibaca; kolom RegistrationNo/ParamedicID/FileName/FilePath terisi.
  • tilaka-lite berjalan; MinIO dan MariaDB sehat; versi sesuai dukungan Tilaka.
  • Key TilakaLite* terisi; folder C:\Tilaka\Signed siap.
  • Dokter uji terdaftar sebagai Quick Sign user dan punya template.
  • Request sign satu signer berhasil sampai DONE.
  • Callback signing dan polling sama-sama teruji; status tidak mundur.
  • Salinan PDF tersimpan lokal dan dapat diunduh lewat handler.
  • Auth interval tampil benar (active/expired/not_activated).
  • Uji negatif: user tanpa sertifikat aktif, template belum ada, MFA gagal, URL kedaluwarsa.
